# Заметки выпуска Moru

Инструкции пользователя имеют приоритет над навыком. Порядок выпуска смотри в [AGENTS.md](../../../AGENTS.md), раздел «Releases»; стиль — в [docs/prompting-codex.md](../../../docs/prompting-codex.md), пункт 12 раздела «Главные правила».

## Контракт заметки

1. Прочитай `version:` в [pubspec.yaml](../../../pubspec.yaml). Для `X.Y.Z+N` дополняй русский файл `docs/releases/vX.Y.Z.md`; номер сборки `+N` не входит в имя файла. [v0.1.47.md](../../../docs/releases/v0.1.47.md) — существующий пример. Повышение версии выполняется отдельной задачей: обновление заметки само по себе не разрешает менять `pubspec.yaml`.
2. Сверь итоговую правку с запросом пользователя и существующей заметкой. Дополни подходящий раздел или добавь короткий тематический раздел, сохранив остальные записи. Сначала опиши конкретное изменение для пользователя: где оно видно и что теперь происходит.
3. Укажи условия работы, значения по умолчанию и существенное ограничение, если они влияют на использование. Для исправления объясни прежнюю проблему и новый результат. Для ускорения описывай наблюдаемое поведение; числа добавляй только по фактическим измерениям.
4. Пиши по-русски простыми глаголами, один абзац — одна мысль. Короткий список подходит для нескольких независимых изменений. Избегай «стоит отметить», «важно», «в общем», выдуманных составных ярлыков и размытых уточнений; ставь пробелы между словами и числами.
5. Если записываешь проверки, отделяй выполненное от оставленного CI или телефону. Указывай только реальные команды и результаты текущей правки: прошлый PR не подтверждает новый прогон. Явное ограничение пользователя на проверки сохраняется; написание заметки не требует запуска приложения, тестов или сборки.

Готово, когда запись соответствует итоговому поведению, текущей версии и подтверждённым проверкам; прежние разделы сохранены, `pubspec.yaml` не изменён без отдельной задачи. В конце задачи кратко сообщи, что изменилось, что проверено и что осталось, по [памятке](../../../docs/prompting-codex.md).

## Примеры PR

| Изменение для пользователя | Проверенный пример |
|---|---|
| Переключатели журналов, полный доступ для отчёта и сведения о медленных кадрах | [#94](https://github.com/mishaqp/Moru/pull/94) |
| Отправка и поток ответа в длинном чате без повторной обработки старой истории | [#96](https://github.com/mishaqp/Moru/pull/96) |
| Необязательные лимиты расходов и инструмент `spend_control` | [#98](https://github.com/mishaqp/Moru/pull/98) |
| Проверка бюджета между запросами многошагового ответа; граница поддержки ACP | [#100](https://github.com/mishaqp/Moru/pull/100) |

Все четыре PR обновляли `docs/releases/v0.1.47.md`. Используй их как примеры уровня подробности и условий работы; факты для новой записи бери из текущей правки.

## Пример поиска

Задача: «Добавлены переключатели журналов; допиши заметку без повышения версии и локальных тестов». Прочитай `version:` в `pubspec.yaml`, открой соответствующий русский файл в `docs/releases`, затем пункт 12 в `docs/prompting-codex.md`. Запиши расположение переключателей и их поведение по готовой правке; сохрани версию и отметь только фактически выполненные проверки. Пример темы — PR #94.
