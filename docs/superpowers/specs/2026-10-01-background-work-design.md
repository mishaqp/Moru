# Надёжная фоновая работа Moru: этап 2

## Цель и границы

Запущенные пользователем ответы, ходы ACP, фоновые shell-команды и серверы
мини-приложений продолжаются при сворачивании и выключении экрана на Android
14–17. Это защита активной работы, а не обещание пережить force-stop, системный
Stop, нехватку памяти или ограничения производителя. После гибели процесса
Moru показывает прерывание и сохраняет сообщения и очередь. Автоматически
повторять старый prompt или команду с побочными эффектами нельзя.

Существующие сохранённые настройки, база, идентификатор приложения и SDK
сохраняются. Новых пакетов и схемы базы не требуется. Работа остаётся в одном
application-owned FlutterEngine. Все новые строки есть в en, ru, zh, zh_Hans,
zh_Hant. Ссылки Markdown, содержащие только #fragment, не открывают файлы.

## Android runtime

Одна существующая GenerationForegroundService использует specialUse на API
34+, видимое уведомление Stop и PARTIAL_WAKE_LOCK только пока есть владельцы.
Подтип явно описывает интерактивную работу ассистента, streaming, ACP/STDIO,
локальные команды, ожидания разрешений и явно запущенные серверы. Выбор не
обосновывается обходом лимита dataSync. Тип не имеет его шестичасовой квоты,
но декларация и демонстрация сценариев подлежат проверке Google Play; отдельная
HTTP-генерация пересекается с примером server-side processing у dataSync.
UIDT не описывает локальные процессы, approval и listening servers.

Владение службой приобретается до запуска длительного процесса и освобождается
после выхода, ошибки запуска, Stop и последнего клиента сервера. Stop отменяет
реальную работу. Неудача запуска службы видна пользователю. Cached idle ACP
session не удерживает CPU после окончания хода. Нельзя запускать скрытую
вечную службу или восстанавливать FGS без восстановления реальной работы.

Native status различает battery exemption, background restriction и Low Power
Standby. Обычный AOSP Doze не требует обязательного исключения при активном
FGS с wake lock. Ненавязчивая подсказка появляется только при активной работе
и отключённой защите, реальном ограничении, предыдущем убийстве процесса или
риске Vivo/Xiaomi. Пользователь может закрыть её; настройки открываются только
по действию. OEM shortcut имеет fallback к настройкам приложения.

## Восстановление

Используется существующий generation_run и startup transition в interrupted;
второй журнал генераций не создаётся. Timeline показывает прерванный ответ,
сохраняя частичный текст, reasoning и инструменты. Продолжение — новое явное
действие и новый run. ACP session ID сохраняется до отправки prompt; восстановление
контекста использует AcpChatSessions load/resume и не повторяет старый prompt.
Нет утверждения, что load/resume продолжает оборванную серверную генерацию.

FIFO постоянных чатов хранится версионированным JSON в существующей
chat_storage_meta_rows, со стабильными UUID и исходным местом редактируемого
сообщения. Подтверждение постановки в очередь происходит после записи.
Удаление queued item выполняется в той же транзакции, что user/assistant/run:
до commit элемент остаётся; после commit остаётся прерванный run, а дубликат
не создаётся. Ошибка записи не очищает draft. Временные чаты остаются временными.
Очередь прерванного чата не запускается автоматически до явной реакции.
Lifecycle flush охватывает все активные чаты, но корректность не зависит от
того, успел ли Android вызвать callback.

## Уведомления

Ready/error публикуются после подтверждённого сохранения результата и до
освобождения владельца службы. Не показываются для отменённого или видимого
чата. Идентификатор каждой карточки не сталкивается с другими чатами.
Error не включает сырые исключения, команды, stderr и секреты.

ToolApprovalService остаётся единственным gate. Каждый pending request имеет
opaque approval UUID и captured chat/run/message; старое действие никогда не
разрешает новый запрос с тем же toolCallId. Private native receiver доставляет
Allow/Deny в существующий main engine через app.mobile_background, без нового
FlutterEngine. Locked-screen action требует аутентификации на API 31+.
Повторные/просроченные/после process-death действия возвращают stale и не
восстанавливаются как очередь разрешений. Native DTO не содержит arguments,
команд и сырого ACP toolCallId. Privacy меняет уже показанные уведомления.
Разрешение POST_NOTIFICATIONS запрашивается только по действию пользователя.

## Проверка

Детерминированные Dart/SQLite тесты проверяют атомарную очередь, interrupted
projection, ACP persistence-before-prompt, строгие approval identities, гонки,
privacy и два чата. Native JVM тесты проверяют тип FGS, wake-lock lifecycle,
receiver, stale actions и collision-free PendingIntent. Общий чеклист AGENTS.md
выполняется до коммитов. На Vivo Android 17 и Pixel проверяются Home, screen-off,
Doze/энергосбережение, shell/server, Allow/Deny, OS kill/force-stop и исключения
батареи. Без телефона эти пункты остаются непроверенными.
