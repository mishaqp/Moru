# Аудит темы и настроек внешнего вида Moru v2

Дата: 1 октября 2026. Область: Android, `ThemeData`, семантические цвета, Glass, шрифты, страницы внешнего вида и поверхности Markdown. Это исследование существующего кода и технические рекомендации; продуктовый код, зависимости и постоянные настройки не изменены. Ссылки `путь:строка` относятся к состоянию рабочего дерева на дату аудита.

## Главный вывод

У Moru уже есть подходящий каркас для единого дизайна: `ColorScheme` → `SurfaceLadder` → `AppSemanticColors` → общие карточки/поверхности. Создавать вторую параллельную тему не нужно. Основная работа — завершить набор семантических ролей, убрать локальные копии строк настроек и привести предпросмотр к той же функции разрешения темы, которую использует приложение.

Новая визуальная палитра должна быть явно выбираемым вариантом. Переписывать сохранённые palette/custom/dynamic/pure/layered/font/bubble настройки при обновлении нельзя: `AGENTS.md:19` требует сохранять явные настройки и данные пользователя. Glass остаётся отдельным необязательным пресетом. Он сейчас меняет сохранённый стиль сообщений и имеет собственное восстановление, поэтому его нельзя трактовать как декоративный флаг новой темы.

## Фактическая сборка цвета и ограничение AMOLED

`AppThemeBuilder` выбирает custom palette по ID и custom объекту, иначе `ThemePalettes.byId`, и применяет dynamic только на Android (`lib/theme/app_theme_builder.dart:78`). Саму доступность dynamic он обновляет после кадра (`lib/theme/app_theme_builder.dart:74`). Общую чистую функцию разрешения темы разумно выделить из этого участка; capability notification следует оставить в widget-слое, чтобы локальный preview не изменял global state.

Фабрика содержит четыре во многом одинаковых конструктора: legacy light/dark (`lib/theme/theme_factory.dart:102`, `lib/theme/theme_factory.dart:273`) и используемые palette light/dark. AppBar fontSize=18, snackbar fontSize=14/radius=12 повторены (`lib/theme/theme_factory.dart:159`, `lib/theme/theme_factory.dart:177`, `lib/theme/theme_factory.dart:233`, `lib/theme/theme_factory.dart:255`). Это реальное место для общих component themes, но рефактор должен сначала сохранять текущие значения и параметры system bars. Корневой `MaterialApp.builder` дополнительно назначает Android overlay style (`lib/main.dart:838`), так что цвет navigation bar из фабрики не единственный источник.

Pure background — существующая настройка, а не новая AMOLED-тема. Light принудительно получает white page (`lib/theme/theme_factory.dart:39`); dark получает black page и inverse colors (`lib/theme/theme_factory.dart:373`). Затем всё равно рассчитываются контейнеры. В legacy dark card — white@10% поверх black (`lib/theme/surface_ladder.dart:68`), в layered card выше page на 11 HCT-тонов (`lib/theme/surface_ladder.dart:93`). Поэтому ожидание «все карточки абсолютно чёрные» текущая настройка не обещает. Для v2 нужно сначала определить контракт pure/AMOLED, сохранив нынешний смысл сохранённого `display_use_pure_background_v1`; не делать скрытую миграцию black → graphite.

Custom theme уже генерирует пары on-colors через `MaterialDynamicColors` и `DynamicScheme`, contrastLevel=0 (`lib/theme/custom_theme.dart:101`). Это хорошая база для акцентов; не следует распространять raw seed непосредственно в кнопки. Произвольные bubble overrides обходят эту гарантию, а translucent поверхности требуют проверки после alpha-compositing с реальным фоном.

## Glass: поведение, которое дизайн обязан сохранить

На странице Glass находятся только enable и economy, через общие rows/cards (`lib/features/settings/pages/glass_theme_settings_page.dart:64`). Это пресет:

1. `setGlassTheme(true)` сохраняет style + assistant overrides + необязательные user overrides в `display_glass_restore_v1` (`lib/core/providers/settings_provider.dart:2725`).
2. Назначает frosted, white rims, assistant opacity=.34/border=.2 и user opacity=.72/border=.28; переносит текущий blur sigma (`lib/core/providers/settings_provider.dart:2731`). User fill получает переданный accent, текст — white при наличии accent (`lib/core/providers/settings_provider.dart:2740`).
3. После notify последовательно записывает restore, message style и glass flag (`lib/core/providers/settings_provider.dart:2752`). Это несколько операций, а не одна атомарная транзакция.
4. При выключении восстанавливает старый snapshot, удаляет restore record; повреждённый snapshot оставляет glass message style (`lib/core/providers/settings_provider.dart:2758`). Ручные изменения стиля, сделанные во время Glass, при выключении уступают snapshot. Это действующий контракт, а не ошибка нового дизайна.

Glass также включает градиент для чата без собственных обоев; wallpaper ассистента имеет приоритет (`lib/features/chat/widgets/frosted/chat_frosted_backdrop.dart:101`). Economy убирает blur у bubble runtime, сохраняя сохранённый sigma (`lib/features/chat/widgets/chat_surface.dart:20`), и отключает blur sidebar (`lib/features/home/widgets/sidebar_glass.dart:45`). Economy не означает автоматического выключения gradient animation.

Есть две конкретные проблемы для контраста/предпросмотра:

- Dynamic Glass берёт один `Theme.of(context).colorScheme.primary` сразу для light и dark (`lib/features/settings/pages/glass_theme_settings_page.dart:22`). Он не получает два динамических ColorScheme. В snapshot user fills фиксируются числовыми ARGB; смена палитры позже сама их не обновляет.
- White текст на светлом dark primary не гарантирует AA. Например, встроенный dark primary `#B6C4FF` (`lib/theme/palettes.dart:88`) даёт с white лишь 1,70:1 на непрозрачной заливке. Новый `#C6BEFF` — 1,72:1; исходный frosted .72 делает результат ещё зависимым от обоев. Выбирать `onPrimary`/`onPrimaryContainer` из схемы при создании новых пресетов и показывать контраст в preview; не исправлять молча сохранённые пользовательские text overrides.

Sidebar Glass — отдельная текущая поверхность: sigma=26, dark/light veil .42/.36 (economy .58/.5), tile .34/.55, rim white/black .10/.06, width=.8 (`lib/features/home/widgets/sidebar_glass.dart:20`, `lib/features/home/widgets/sidebar_glass.dart:60`, `lib/features/home/widgets/sidebar_glass.dart:92`). Эти числа стоит собрать в роль glassSidebar, чтобы она не конкурировала с bubble resolver; это разные задачи и разные blur.

## Шрифты: реальный pipeline и границы предпросмотра

В `pubspec.yaml:39` есть `lucide_icons_flutter`; `google_fonts` не используется. Google Fonts — свой сервис: каталог Expo API snapshot на GitHub, regular face, TTF только с `fonts.gstatic.com`, лимиты catalog=8 MiB/font=64 MiB, cache на семь дней (`lib/core/services/fonts/google_fonts_service.dart:38`, `lib/core/services/fonts/google_fonts_service.dart:64`, `lib/core/services/fonts/google_fonts_service.dart:100`). Загрузка лицензии обязательна, сетевые редиректы отключены, сервис отменяет запросы при close (`lib/core/services/fonts/google_fonts_service.dart:144`, `lib/core/services/fonts/google_fonts_service.dart:172`). Это существующая функция, которую нужно сохранить без добавления другой font dependency.

Picker уже умеет безопасный локальный preview: FontLoader регистрирует временное family имя, URI cache разделяет завершённые и конкурентные загрузки; шрифт остаётся в engine до конца процесса (`lib/features/settings/pages/google_fonts_picker_page.dart:47`). Только Apply вызывает импорт через provider (`lib/features/settings/pages/google_fonts_picker_page.dart:170`). Нажатие выбора/загрузки не должно быть автоматически перенесено в global appearance setter.

Local import копирует файл в app fonts directory, сохраняет `.license.txt`, проверяет TTF/OTF/TTC сигнатуру и регистрирует FontLoader alias (`lib/core/providers/settings_provider.dart:2093`, `lib/core/providers/settings_provider.dart:2143`). Замена/сброс удаляет прежний managed файл, если его больше не использует app/code font (`lib/core/providers/settings_provider.dart:1841`, `lib/core/providers/settings_provider.dart:2126`). Alias фактически содержит timestamp, хотя комментарий называет его stable (`lib/core/providers/settings_provider.dart:2148`); нужно избегать повторной регистрации на каждом движении slider.

На cold load существующая миграция очищает legacy Google flags и недоступные старые families; local fonts повторно регистрируются (`lib/core/providers/settings_provider.dart:1960`). Не связывать введение tokens с новой глобальной миграцией font keys. Старые и импортированные локальные шрифты должны продолжать работать.

Global app font применяется к обоим text themes и AppBar через `_withFont`, затем через root `DefaultTextStyle.merge` (`lib/theme/app_theme_builder.dart:117`, `lib/main.dart:906`). Snackbar custom `contentTextStyle` не обрабатывается `_withFont`; нужны проверки наследования фактически отображаемого текста, а не предположение «каждый custom TextStyle уже использует app font». Markdown code самостоятельно берёт code font, fallback `monospace` (`lib/shared/widgets/markdown_with_highlight.dart:2913`). Большинство terminal/tool/log мест имеет собственный `monospace`; изменение app font не должно менять код и журналы случайно.

Android fallback уже корректно выделен: `sans-serif` (`lib/theme/theme_factory.dart:18`); новый дизайн не должен навязывать iOS font stack. `AppFontWeights.normalize` на Android превращает w500 в w400, а w600+ в w500 (`lib/theme/app_font_weights.dart:16`). Для «сильной типографики» сначала учитывать фактически отображаемый вес; все нынешние labels semibold не являются w600 на Android. Google picker импортирует один regular face; поддержку нескольких весов/variable axes нельзя обещать только изменением tokens. В sample обязательны русский, латиница, CJK, emoji и код.

### Иконки и доступность

Основные theme/display/message settings используют адаптер `Lucide.*` (`lib/icons/lucide_adapter.dart:6`), как требует `AGENTS.md`. В просмотренных страницах нет прямых Material Icons. В чате остаются `Icons.broken_image` и `Icons.insert_drive_file` (`lib/features/chat/widgets/chat_message_widget.dart:377`, `lib/features/chat/widgets/chat_message_widget.dart:1988`, `lib/features/chat/widgets/chat_message_widget.dart:2178`); это узкий последующий cleanup с заменой на существующий adapter, а не причина сменить icon package.

В общих кнопках есть optional minSize и semantics; Glass/message AppBar передают minSize=44 и semanticLabel (`lib/features/settings/pages/glass_theme_settings_page.dart:48`, `lib/features/settings/pages/message_style_settings_page.dart:41`). Theme использует старый локальный tactile button; copy/edit/delete custom row не имеют своих Tooltip/semanticLabel (`lib/features/settings/pages/theme_settings_page.dart:242`). В unified components фиксировать Android touch target минимум 48 dp для новых controls; существующие 44 dp оценить отдельным срезом, не уменьшать площадь ради компактного дизайна. У `IosSwitch` hitTestSize=44 и animationDuration=220 ms (`lib/shared/widgets/ios_switch.dart:24`).

## Markdown, код и другие поверхности сообщения

Эта palette ориентируется только на brightness, не на accent/custom/AMOLED. Перенести в diagram/code semantic roles отдельно от цветов самой диаграммы. |
| Общие alpha | `lib/shared/widgets/markdown_with_highlight.dart:63` | Details=.55, inline=.40, table=.72, code=.80 — явная политика просвечивания обоев. Не менять все fills на opaque в рамках механической замены hex. |

Передача theme цвета участвует в cache key Markdown (`lib/shared/widgets/markdown_with_highlight.dart:412`). В нём перечислены brightness/surface/ink/primary/outlineVariant/fonts, но не все новые extension-поля. При введении отдельного code/diagram extension нужно пересмотреть invalidation, иначе preview может сохранить часть старого цвета. Theme-independent syntax parse cache уже специально переживает переключение темы (`lib/shared/widgets/markdown_with_highlight.dart:81`); не нужно сбрасывать весь parse cache ради recolor.

## Почему существующий preview пока не равен приложению

Message style уже имеет preview с user/assistant/reasoning и настоящим `FrostedSurface` (`lib/features/settings/pages/message_style_preview.dart:3`, `lib/features/settings/pages/message_style_preview.dart:87`, `lib/features/settings/pages/message_style_preview.dart:235`). Это полезная основа для нового экрана, но сейчас это отдельная simplified сцена и отдельная сборка тем:

- `_previewThemes` использует current theme для текущей brightness, противоположную строит напрямую из статической/custom palette; app font и противоположный dynamic scheme не применяются (`lib/features/settings/pages/message_style_settings_page.dart:425`, `lib/features/settings/pages/message_style_settings_page.dart:444`).
- Cache key содержит custom ID, но не его ARGB/объект, app font или effective dynamic values (`lib/features/settings/pages/message_style_settings_page.dart:429`). Редактирование выбранной custom theme с тем же ID не обязано инвалидировать обе кэшированные темы.
- Preview fixed height=220, max bubble width=240 и text sizes=14/13 (`lib/features/settings/pages/message_style_preview.dart:35`, `lib/features/settings/pages/message_style_preview.dart:107`, `lib/features/settings/pages/message_style_preview.dart:120`). На крупном text scale он рискует overflow, не воспроизводит chat font scaling и не показывает настоящий Markdown/code/tool content.
- `_PreviewSurface` повторяет solid/default ветки реального `buildSharedChatSurface`; оба используют один bubble resolver, но preview не применяет economy blur override из runtime selection (`lib/features/settings/pages/message_style_preview.dart:230`, `lib/features/chat/widgets/chat_surface.dart:20`).
- `MobileBackgroundLayer` и backdrop resolver читают реальные assistant/settings providers; одного вложенного `Theme` недостаточно для preview нового Glass/gradient/wallpaper draft.

Поэтому дизайн preview должен показывать достоверный небольшой фрагмент беседы с body, inline code, fenced code, reasoning/tool status, composer и settings row. Он не должен запускать генерацию/агента, менять выбранного ассистента, загружать историю или использовать callbacks реального чата.

## Практический путь к unified tokens и live preview

1. **Единый resolver без записи.** Выделить immutable snapshot только полей appearance и чистую сборку light/dark из palette/custom, optional dynamic schemes, pure/layered, font. `AppThemeBuilder` и preview используют её. В snapshot сохраняются оба app/code fonts, chat font scale, styles обеих ролей, Glass/economy и фоновые параметры; runtime capability notification остаётся вне resolver. Не копировать весь SettingsProvider.
2. **Одна цветовая система.** Сохранить `ColorScheme` для Material roles и расширить существующие semantic roles точечно: dedicated inline/code/diagram surfaces, вторичный/приглушённый текст, selected/pressed fill там, где roles действительно повторяются. Geometry/typography/motion объявить рядом с нынешним `design_tokens.dart`, сначала со старыми числами. Не создавать десятки произвольных «color1/color2» и per-page тем.
3. **Отдельный appearance draft.** Live preview реагирует на локальный draft, неизменный baseline содержит текущие значения и nullable defaults. Cancel/back уничтожает draft, а не «откатывает» десятки уже выполненных setters. Apply сохраняет только изменённые appearance поля, с явной обработкой результата; сохранённые unrelated settings не копируются обратно.
4. **Glass как операция draft.** Применять пресет к draft чистой функцией, отображать изменяемые style/user/assistant значения. Только итоговое подтверждённое Apply может менять реальный restore record. Не включать/выключать глобальный Glass для демонстрации вариантов. Текущая логика multiple writes требует отдельной проверки partial failure; не заявлять атомарность без нового repository API/тестов.
5. **Шрифты в staging.** Повторно использовать picker preview loader и существующий local importer, а permanent copy/delete предыдущего файла делать только при Apply. Cancel очищает temp download/license, но уже registered engine font нельзя «выгрузить» обещанием в UI. Cache и ограниченная регистрация предотвратят загрузку каждого шрифта каталога в память.
6. **Переиспользуемая сцена.** Preview получает resolved themes/bubble styles/backdrop spec явно. Общая surface branch должна быть одна; реальные widgets можно использовать только с безопасными статическими данными и отключёнными действиями. `ChatFrostedBackdrop` должен корректно завершать lease/image ownership при переключении draft. Для wide Android/tablet layout не добавлять desktop targets.
7. **Новый визуальный вариант только opt-in.** Новая палитра имеет новый стабильный ID и локализованное имя; существующие IDs и saved custom names сохраняются (`lib/theme/palettes.dart:22`). Первое открытие нового appearance editor начинается с текущего snapshot, а не с mockup defaults. Изменение нового default для fresh install — отдельное явно описанное решение.

`SettingsProvider.copyWith` не решает draft isolation: он создан для search options, использует тот же `_preferences` (`lib/core/providers/settings_provider.dart:5780`, `lib/core/providers/settings_provider.dart:5787`), а его setters продолжают писать реальные данные. `updateSettings` также обновляет только search (`lib/core/providers/settings_provider.dart:5762`). Применять эти методы к appearance preview опасно и неполно.
