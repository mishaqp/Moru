# Аудит runtime и чата перед редизайном v2

Дата: 2026-10-01. Это статический аудит текущего дерева, а не результат запуска APK на телефоне. Прочитан `AGENTS.md`; исходники, зависимости, ветка и настройки не изменены. Цель — Android, управление одной рукой, сохранение истории, workspace/PRoot/PTY/STDIO и существующих разрешений. До завершения аудита экраны не рисовались.

## Что уже можно проектировать

Основные функции существуют. Новый нижний вход в инструменты, более читаемая лента действий, полный просмотр очереди и удобные карточки разрешений — преимущественно работа над UI. Переписывать генерацию, ACP transport, файловую границу, terminal manager или planner для этого не требуется. Подробная общая панель всех процессов и полная сводка изменений требуют явного контракта данных; нынешние сведения частичны и имеют разный срок жизни.

Не смешивать три понятия:

- **Ассистент Moru** — сохранённый профиль: prompt, модель/provider, memory, local tools, MCP, default workspace. Поля видны в `lib/core/models/assistant.dart:35`, `:55`, `:60`, `:88`.
- **Обычная LLM с workspace tools** — модель отвечает через штатный API, а Moru выполняет shell/file/plan tools. `WorkspaceToolsService` обслуживает определения, policy и исполнение (`lib/core/services/workspace/workspace_tools_service.dart:53`, `:76`).
- **Внешний ACP agent** — установленный Linux-процесс; `Assistant.agentId` заменяет источник ответа, выбранная модель задаёт ему provider/key/model (`lib/core/models/assistant.dart:44`). Его file/shell действия исполняет сам агент и сообщает ACP. Это не ещё один локальный tool и не доказательство существования multi-agent orchestration.

### Plan и работающие команды

`ComposerStatusStrip` читает **последний plan этого чата** и **workspace ToolRun этого чата**. Plan показывается только во время генерации и пока не done; после ответа остаётся собственная `update_plan` карточка, если такой вызов был. Из нескольких команд strip показывает последнюю и `+N`, не список (`lib/features/home/widgets/composer_status_strip.dart:44`, `:85`). Комментарий о plan lifetime находится там же `:22`.

`TaskPlanRegistry` — in-memory map, без БД, истории, процентов, deadline или связи шаг→tool (`lib/core/services/workspace/task_plan.dart:15`, `:57`). Plan — текст и pending/inProgress/completed; текущий выбирается сначала inProgress, затем pending (`:25`). Для LLM checklist идёт из `update_plan`; ACP `sessionUpdate=plan` обновляет registry, **не создаёт сохранённую tool card** (`lib/core/services/acp/acp_turn_translator.dart:52`, `:275`). Нельзя обещать восстановленный ACP plan после убийства процесса.

`ToolRunRegistry` тоже process-lifetime: running/succeeded/failed/cancelled/timedOut, runtime id, tool id, startedAt, command, exitCode, bounded stdout/stderr; завершённая история ограничена 200 (`lib/core/services/workspace/tool_run_registry.dart:8`, `:22`, `:43`, `:140`, `:234`). `RunningToolChip` показывает elapsed, последний output line, Stop; detail использует live run и открывается существующим bottom sheet (`lib/features/home/widgets/running_tool_bar.dart:55`, `:62`, `:122`; `lib/features/chat/widgets/workspace_tool_detail.dart:67`, `:118`). Stop имеет 32×32 target (`running_tool_bar.dart:157`), малый для одной руки.

Shell уже поддерживает `background:true`, отдаёт `job_id`, а `shell_output` читает/ждёт/останавливает его; запускается свежий неинтерактивный shell, cwd/env между calls не сохраняется (`lib/core/services/workspace/workspace_tools_service.dart:89`, `:265`, `:943`, `:1017`, `:1277`). Этот job не равен пользовательской PTY-вкладке. После гибели процесса live registry не является resumable job store.

Пример честного статуса: «Ответ выполняется · требуется решение» выводится из active generation + pending approval; «команда `npm run dev` · 1:12» — из ToolRun. «Агент выполнил 70% проекта» данных не имеет. Plan progress N/M — доля отмеченных моделью пунктов, а не оценка оставшегося времени.

## Tools, diff, ошибки и разрешения

`WorkspaceToolMetadata` сохраняется на tool part и не идёт в model input. Уже есть status/code/path/files/command/exitCode/duration/timedOut/cancelled/interrupted/stdout/stderr/**nullable diff/added/removed/diffTruncated** (`lib/core/services/workspace/workspace_tool_metadata.dart:6`, `:38`, `:52`). `WorkspaceToolFile` различает referenced/created/modified/log, directory/temporary и produced (`lib/core/services/workspace/workspace_tool_file.dart:1`, `:20`). Эти данные и существующий `UnifiedDiffView` можно переиспользовать для деталей и файлов ответа.

Пределы: это metadata отдельных вызовов, а не полный git diff, транзакция или rollback. Shell определяет изменения по mtime snapshots, ограниченным 20 000 entries, пропускает dot directories/node_modules/__pycache__, сравнивает только присутствующие после вызова файлы (`lib/core/services/workspace/conversation_files.dart:5`, `:8`, `:14`, `:29`). Он не предоставляет old/new content или надёжную историю удалений. ACP создаёт diff только если агент прислал `content.type=diff` с path/oldText/newText; location берётся первым, failed edit имеет referenced role (`lib/core/services/acp/acp_turn_translator.dart:333`, `:340`, `:418`, `:450`). Возможная «сводка файлов ответа» — частичная. Полная «проверка всех изменений workspace», несколько diff по одному call и применить/откатить требуют нового scope/API.

Pending approval — live `Completer`, scoped по `(conversationId,toolCallId)`; есть approvalId и owner run/message с проверкой живого исполнения (`lib/features/home/services/tool_approval_service.dart:47`, `:82`, `:164`). После stop запрос отменяется; старое notification decision должно считаться stale, и exact identity проверяется (`:227`, `:265`). Это не durable promise после process death.

Сейчас есть разные уровни policy, их надо называть явно:

- Глобальный `toolAutoApproveAll` сохранён в preferences, default false; его включение разрешает уже ожидающие live requests (`lib/core/providers/settings_provider.dart:1187`, `:5571`; `lib/features/home/services/tool_approval_service.dart:90`). Это существующий пользовательский выбор, а не temporary consent карточки.
- Workspace shell approval зависит от workspace `shellNeedsApproval`, sandbox и conversation binding `allowAll`; read-only mounts/skills/outside sandbox отказываются на границе (`lib/core/services/workspace/workspace_tools_service.dart:901`, `:1848`; `lib/core/models/workspace_binding.dart:5`). Не заменять эти policies красивым общим переключателем.
- ACP Allow предпочитает `allow_once`, Deny — `reject_once`, с fallback на подходящую advertised option (`lib/features/home/services/acp_chat_bridge.dart:254`, `:274`). Текущий UI не представляет agent options «всегда разрешать инструмент/проект». Для такой функции нужен отдельный policy/persistence contract; нельзя выводить её из общего trust switch.

Android friction: generic approval button 36px height (`lib/features/chat/widgets/workspace_tool_ui.dart:319`), workspace chain использует маленькие icon approvals (`lib/features/chat/widgets/chat_message_widget.dart:5688`), deny может открыть диалог причины (`lib/features/chat/widgets/workspace_tool_ui.dart:347`). Нижний лист с читаемой командой/пути/эффектом и 48dp действиями возможен поверх текущего сервиса. Approval всё равно должен показывать **тот же** redacted display payload и разрешать именно live request, не свежий похожий tool id.

ACP failure уже сохраняется отдельно как `AgentErrorPart`, diagnostic details не становятся будущим prompt (`lib/core/models/message_part.dart:42`), stream handler сохраняет partial response + failed generation (`lib/features/home/controllers/chat_actions.dart:3485`, `:3510`). OAuth имеет отдельный `ProviderAuthErrorPart` (`lib/core/models/message_part.dart:78`). Interrupted notice — отдельный UI с Continue, учитываемый в height estimate (`lib/features/home/widgets/interrupted_reply_notice.dart:9`, `:15`, `:74`). Переиспользовать эти recovery actions; единый красный toast потеряет полезную историю и действие.

## ACP agents: установка, запуск и честный статус

Каталог: Claude Code, Codex, OpenCode, Kimi Code, DeepSeek Harness и custom command (`lib/core/services/acp/acp_agent_catalog.dart:342`, `:427`, `:442`, `:453`, `:479`, `:491`; custom parsing `lib/features/agents/pages/agents_page.dart:112`). `AgentsPage` показывает install label и открывает detail (`:75`), detail уже имеет install/update/remove/check/start-chat, опциональные Web open/stop, log и MCP probe result (`lib/features/agents/pages/agent_detail_page.dart:131`, `:176`, `:209`, `:274`). Это готовые маршруты, не placeholders.

`AcpAgentManager` installation state — unknown/missing/installed; busy/probing/check/error отдельно и преимущественно в памяти (`lib/core/services/acp/acp_agent_manager.dart:25`, `:99`). Check запускает agent initialize и реально проверяет loopback из текущего runtime (`:451`, `:477`); installed не значит provider совместим, процесс отвечает или MCP доступен. Codex конфиг всегда `wire_api="responses"` (`lib/core/services/acp/acp_agent_catalog.dart:589`), picker и detail предупреждают об API (`lib/features/agents/widgets/assistant_agent_card.dart:64`, `:112`). Не рисовать всем agents один «готов» из installed boolean.

`assistantForAgent` повторно использует первый профиль с таким agentId или создаёт профиль; Start chat создаёт **новый чат**, делает ассистента current и возвращает Home (`lib/features/agents/agent_chat_start.dart:10`, `:25`). Agent picker сохраняет agentId в профиль (`lib/features/agents/widgets/assistant_agent_card.dart:79`). Отделить на экране «модель/provider», «кто отвечает» и «рабочая папка»: пользователя иначе путает одинаковая модель у двух разных execution engines.

ACP bridge автоматически создаёт/привязывает default workspace для постоянного чата при необходимости (`lib/features/home/services/acp_chat_bridge.dart:144`, `:215`). `_executeGeneration` хранит, стримит и завершает ответ прежним pipeline; только источник chunks меняется (`lib/features/home/controllers/chat_actions.dart:2878`). `AcpChatSessions` держит один живой процесс/session на chat, переиспользует его при прежнем launch key, меняет при новом и закрывает через 20 минут idle (`lib/core/services/acp/acp_chat_sessions.dart:66`, `:173`). Сохранённые extras содержат `acp.session={agent,id}` и `acp.mode`; restoration пытается load, затем advertised resume, иначе новую session с текстовой history (`lib/features/home/services/acp_chat_bridge.dart:27`, `:188`; `lib/core/services/acp/acp_chat_sessions.dart:194`). Это восстановление **контекста**, не продолжение оборванного prompt с байта.

Mode chip появляется лишь у живой session с непустыми advertised modes; сохраняет выбор для следующего turn (`lib/features/home/widgets/acp_mode_chip.dart:12`, `:26`, `:59`). ACP plan/modes/images/restore — capabilities, не обязательный набор. Translator понимает text/thought/tool/plan, другие update extensions не отображает (`lib/core/services/acp/acp_turn_translator.dart:42`); execute/read/edit/search показываются знакомыми workspace cards (`:364`), но **не создают Moru ToolRun с live stdout и локальным runtime id**. Поэтому running-command chip нельзя автоматически выдавать за список всех ACP command executions.

Агент получает Moru browser/miniapps/memory/schedules через owned authenticated loopback MCP; file/shell и сторонние MCP исключены (`lib/core/services/acp/acp_mcp_server.dart:32`, `:41`, `:58`). Handler проверяет актуальный assistant/tool enablement и live owner; browser требует visible/resumed chat (`lib/features/home/services/acp_moru_tools.dart:68`, `:106`). Сохранять связь MCP call↔ACP card, env-only secrets и display redaction, иначе новый activity view может раскрыть launch credentials или выдать два approval на одно действие. Существующая граница origin/token не заменяется WebView JavaScript bridge (`lib/core/services/acp/acp_mcp_server.dart:79`).

## Miniapps и scheduled tasks

Miniapps — работающий runtime, не экран каталога демо. `MiniAppStore` сохраняет manifest/data/errors/versions, сохраняет data при republish (`lib/core/services/mini_apps/mini_app_store.dart:175`, `:286`). Apps notifier готов, errors/jobs badges обновляются из disk после store change и resume (`lib/features/mini_apps/pages/mini_apps_page.dart:56`). Поиск появляется с пяти apps, menu — long press/36px ⋯ (`:38`, `:222`, `:262`). Список v2 может переиспользовать store/page routes, отдельно показать launch/settings/errors/jobs в большом нижнем листе.

Server badge списка обозначает **наличие server declaration**, не живой process (`lib/features/mini_apps/pages/mini_apps_page.dart:317`). Настоящий status есть у `MiniAppServers.status`, current sheet опрашивает его раз в секунду (`lib/core/services/mini_apps/mini_app_servers.dart:96`; `lib/features/mini_apps/widgets/mini_app_sheets.dart:366`). Для reactive runtime tile нужен небольшой adapter над этим API. «Остановить приложение» и «остановить сервер» не взаимозаменяемы: server может обслуживать job.

Miniapp jobs хранят definition в app store и планируются native scheduler; list объединяет nextRun/runs native, rescheduleAll восстанавливает расписание (`lib/core/services/mini_apps/mini_app_jobs.dart:148`, `:189`, `:217`). `MiniAppJobRunner` использует hidden WebView, с отдельными load/run timeouts 15/30 seconds (`lib/features/mini_apps/mini_app_job_runner.dart:17`, `:109`). Jobs сейчас доступны My Apps→⋯→jobs; label содержит JS function (`lib/features/mini_apps/widgets/mini_app_sheets.dart:321`). Переиспользовать list/runNow/remove и хранение; presentation для обычного пользователя не должна требовать понимать имя JS-функции.

Scheduled chat tasks тоже существуют: native `SharedPreferences.commit`, alarms без Dart isolate, killed run переводится interrupted, history ограничена chat20/job5 (`android/app/src/main/kotlin/com/psyche/kelivo/scheduled/ScheduledTasks.kt:20`, `:36`, `:46`, `:183`, `:245`). Chat schedules нуждаются в exact alarm permission; jobs могут быть inexact (`:211`); native deadlines chat10min/job90sec (`:29`, `:252`). Это не абсолютное обещание запускать вовремя под OEM restrictions.

Dart service имеет observable tasks/exactAlarms/error, page обновляет при resume (`lib/core/services/scheduled_tasks_service.dart:51`, `:163`; `lib/features/scheduled_tasks/pages/scheduled_tasks_page.dart:69`). Sheet предлагает run/history/edit/delete (`:120`), running task нельзя toggle (`lib/features/scheduled_tasks/widgets/scheduled_task_tile.dart:83`). **Публичного individual cancel API/UI сейчас нет**: service даёт save/delete/runNow (`lib/core/services/scheduled_tasks_service.dart:200`). Общий native Stop tasks есть; для отдельной Stop task кнопки нужен новый targeted cancel contract, а не декоративный control.

## Memory, голос и overlays

Memory v2 хранится в typed DB через transactional repository; CRUD/search/archive/restore уже готовы (`lib/core/providers/memory_provider_v2.dart:82`, `:119`; `lib/core/services/memory/memory_repository.dart:35`). Сохранять scopes/types/provenance/archive, не подменять её простым строковым списком. Ошибка `refresh` сейчас очищает entries/profileFields и не экспортирует loading/error: UI не различает «пусто» и сбой чтения (`lib/core/providers/memory_provider_v2.dart:98`). Это требует небольшого provider contract исправления, если v2 обещает полноценные empty/error states.

`MemoryPipeline` имеет ограниченную очередь 8 и private `_running`, `lastStatus` — обычный getter, не самостоятельный listenable (`lib/core/services/memory/memory_pipeline.dart:143`). Trace observable, держит последние 24, не persist (`lib/core/services/memory/memory_trace.dart:272`). Для «memory сейчас организуется / ждёт / ошибка» нужен observable runtime snapshot, а не guessed status. Filters/add/batch delete находятся в одном горизонтальном ряду; Add может оказаться после scope/type/status/select за экраном (`lib/features/settings/pages/memory_entries_page.dart:162`). Editors/pickers переиспользовать, primary Add выделить снизу.

ASR — единая реальная session state idle/connecting/listening/transcribing/error с transcript/soundLevel, system/local/cloud backend (`lib/core/providers/asr_provider.dart:13`, `:65`, `:93`). Composer поддерживает stop→input и send→dispatch (`lib/features/home/widgets/chat_input_bar.dart:961`), localized error snackbar (`:882`), session cancel при dispose/switch (`:613`, `:657`). Не нужен новый ASR backend; нужны крупные controls, ясное transcribing/error/retry и сохранение draft. Нельзя показать always listening: microphone session принадлежит provider и имеет owner/lifecycle.

TTS имеет state/position/speed/error, pause/seek/replay/save (`lib/core/providers/tts_provider.dart:59`, `:100`, `:605`), config persist, replay chunks in-memory (`:123`, `:59`), temporary audio cleanup (`:1079`). Global player и floating browser вместе живут в `AppOverlays` (`lib/shared/widgets/app_overlays.dart:18`); player starting position safeTop+68 и controls32px (`lib/shared/widgets/tts_floating_player.dart:88`, `:439`, `:477`). Lower reachable dock/overlay arbitration возможны поверх текущего playback API; source-message association и конфликт с composer/browser требуют controller/UI adapter. Не обещать replay current session после process death без сохранённого audio/artifact.

## Фоновая работа и уведомления

Общий **native aggregate active work уже существует**. `MobileBackgroundCoordinator` хранит live task id/chat/message/title/start/phase/tokens, публикует serial whole snapshots; public `hasActiveWork` учитывает native `activeOwners` (`lib/core/services/mobile_background.dart:14`, `:26`, `:56`, `:83`). Native status содержит activeTasks/keepAliveOwners/scheduledRuns/pendingApprovals/activeOwners, FGS и системные разрешения (`android/app/src/main/kotlin/com/psyche/kelivo/background/BackgroundRuntime.kt:400`). Phase текста notification — requesting/generating/thinking/tool/retrying (`lib/core/services/mobile_background.dart:497`).

Это хорошая база для «есть активная работа» и background reliability. Но `_tasks` private, snapshot — транспортный payload; status содержит counts, а не публичный список всех PTY/ACP-Web/miniapp-process owners с типом, workspace и собственным Stop. Для подробного общего activity sheet нужен read-only adapter или API над текущими owners, с явным source/capability/stop target. Один aggregate count не доказывает, что пользовательский terminal выполняет команду.

Pending approval зеркалится в уведомление только с live owner; exact approval/run/message identifiers сохранены, generic body не несёт tool args (`lib/core/services/mobile_background.dart:143`). Результат уведомляется после persistence и учитывает privacy/visible chat/browser Ask-AI (`:348`, `:377`, `:559`). Warm/cold notification opens уже сохраняют target до готовности Home и умеют открыть исходный message (`lib/core/services/notification_service.dart:149`, `:245`, `:257`). `ProcessKeepAlive` умеет hold/release и native Stop released stream (`lib/core/services/keep_alive.dart:17`, `:36`, `:41`). Переиспользовать эти каналы, не делать второй foreground service/FlutterEngine.

После kill частичный ответ и generation interrupted сохраняются, FIFO постоянных чатов удерживается, старые shell/approval не переисполняются; ограничения устройства описаны в `docs/android/background-work.md:63`. Нельзя обещать «всегда работает в фоне», незаметное auto-resume commands или продолжение после force-stop. Lock screen/OEM Doze/Stop требуют device проверки; статический аудит её не заменяет.

## Риски реализации UI

1. **Scroll.** Lazy variable-extent timeline использует projector для renderer и estimator (`lib/features/home/widgets/message_list_view.dart:74`, `:805`). Height estimates содержат constants и content/settings signatures (`:528`, `:652`); менять высоты tool/reasoning/approval/image только совместно с ними. Keyboard, нижняя панель, plan expansion и completion меняют extent; существующий layout-time autofollow уступает реальному gesture (`lib/features/home/controllers/scroll_controller.dart:17`, `:30`, `:125`). Не заменять его `jumpTo` после каждого token.
2. **Perf.** Streaming notifier обновляет конкретное message, tool-height events coalesced (`lib/features/home/controllers/streaming_content_notifier.dart:57`, `:180`), live output throttled 50ms и bounded (`lib/core/services/workspace/tool_run_registry.dart:43`). Новый «Выполняется» должен слушать нужные поля, не весь Home/Provider. Не монтировать несколько live WebView/terminal panes в каждой chat card. Composer уже использует blur 14 (`lib/features/home/widgets/chat_input_bar.dart:2351`); дополнительная animated glass layer нуждается в profile на arm64 телефоне.
3. **Security.** Файлы/UI/tools должны проходить общую `WorkspaceFileAccess`: real roots/read-only roots, symlinks и checked fd, а preview — private checked snapshots (`lib/core/services/workspace/workspace_file_access.dart:19`, `:39`; полный contract в `AGENTS.md`). UX открытия файла не даёт модели новый root. Сводки/clipboard/logs получают redacted display data, execution handlers — оригинал; не вставлять browser/agent-Web credentials в URL или history.
4. **Permission persistence.** Развести saved global trust, workspace binding policy, Android notification/overlay/microphone permissions и one-call live approval. Не обещать persistent approvals и не replay старый allow. Смена чата, stop, kill и поздняя notification action должны проверять live owner.
5. **Одна рука.** Primary actions доступны снизу, 48dp targets, системный Back закрывает sheet/keyboard без потери draft. Действующий header switcher вверху имеет targets 36×30 или 48×34 (`lib/features/home/widgets/chat_header_switcher.dart:113`); перенос нижних входов может переиспользовать те же navigation methods. При keyboard+queue+plan не закрывать весь ответ и не оставлять Stop за overflow.
