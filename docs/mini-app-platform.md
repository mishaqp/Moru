# Ядро мини-приложений 2.0

Версия Moru остаётся 0.1.47+48. Старый `moru-app.json` без `formatVersion`
считается форматом 1 и открывается в WebView. Его файлы, `moru.storage`,
задания, серверы, версии, экспорт и резервные копии сохраняются.

## Манифест и действия

```json
{
  "id": "brightness-panel",
  "name": "Яркость",
  "formatVersion": 2,
  "ui": {"engine": "native", "entry": "screen.json"},
  "permissions": ["actions.ai", "device.screen.read", "device.screen.write"],
  "actions": [{
    "name": "brightness",
    "description": "Изменить общую яркость",
    "inputSchema": {
      "type": "object",
      "properties": {"value": {"type": "integer", "minimum": 0, "maximum": 255}},
      "required": ["value"],
      "additionalProperties": false
    },
    "permissions": ["device.screen.write"],
    "danger": "write",
    "executor": {"kind": "native", "handler": "device.screen.brightness.set"}
  }]
}
```

`ui.engine` принимает `web` или `native`. Действие объявляет имя, описание,
исходную JSON Schema, права, опасность `read`/`write`/`root` и исполнителя.
Приложение не может ослабить права или подтверждение фиксированного обработчика.
Схема проверяется при установке и перед выполнением; неизвестные проверяемые
ограничения отклоняются. Корень аргументов описывает объект, включая локальные
ссылки и композиции объектных схем. Проверка ограничивает объём, глубину и
разворачивание ссылок; `pattern` принимает безопасное подмножество без групп,
альтернатив и обратных ссылок. Исходная схема сохраняется без переписывания.
Необязательный null, который исходная схема запрещает,
означает отсутствие аргумента; разрешённый null остаётся данными.

При включённом инструменте ассистента `mini_apps` действия становятся
`ma_`-инструментами с ограниченным именем и хешем app/action ID. Их имена
резервируются от коллизий с MCP. Для выполнения из ИИ приложение должно иметь
выданное пользователем право `actions.ai`; оно требуется и для записи/удаления
данных формата 2 через `mini_apps`. Обычный чат и ACP вызывают тот же
`MiniAppRuntime.execute`, что кнопка. Снимок маршрутов на время ответа не даёт
обновлению приложения подменить уже предложенное действие.

Исполнители первой части: `native` с фиксированным `handler`; `state` с
`patch`, где `{"$arg":"имя"}` подставляет аргумент; `preset` с ограниченным
списком `steps: [{handler, args}]`; `restore` без пользовательской записи
в журнал восстановления. Новые исполнители добавляются в проверку манифеста и
общий runtime. Интерфейсы экрана, чата и ACP сохраняются.

## Экран и состояние

```json
{
  "version": 1,
  "components": [{
    "type": "card", "title": {"ru": "Экран", "en": "Screen"},
    "children": [{
      "type": "slider", "label": {"ru": "Яркость", "en": "Brightness"},
      "bind": "device.screen.brightness", "min": 0, "max": 255, "step": 1,
      "action": "brightness", "args": {"value": {"$value": true}}
    }]
  }]
}
```

Компоненты: `card`, `text`, `value`, `button`, `switch`, `slider`, `list`,
`indicator`. Числовой индикатор показывает шкалу между `min` и `max`, логический —
состояние. `bind` читает путь в `data`, `device` или `revision`.
`action` ссылается на объявленное действие; `$value` подставляет значение
контрола. Ползунок применяет значение при отпускании. Строки могут содержать
карты локалей. JSON ограничен по размеру, глубине и числу компонентов;
исполняемых строк и загружаемых плагинов нет.

`mini_apps` с `action: state` читает снимок открытого или закрытого приложения.
WebView формата 2 использует `moru.actions.invoke(name, args)`,
`moru.state.get()`, `moru.state.subscribe(listener)` и `moru.device.*`.
Подписка возвращает функцию отмены. Снимок содержит `data`, отфильтрованный
по выданным правам `device` и `revision`. Android сообщает реальные изменения;
при возвращении из настроек экран перечитывает их. Закрытая нативная панель
не держит WebView, сервер, процессы или постоянный наблюдатель Android.

## Доступ к телефону

Пользователь выдаёт и отзывает отдельные права на экране приложения.
Установка и обновление не выдают новых прав; grants и журнал восстановления
хранятся отдельно от доступного приложению `data.json` и экспорта `.moruapp`.
Полный доступ снимает подтверждение Moru, сохраняя права приложения,
Android-разрешения, типы, пределы и список операций. После ожидания согласия
проверяются актуальные права, версия и владелец вызова.

Группы чтения: батарея, экран, звук, связь, фонарик и система. Для записи:
`device.screen.write`, `device.audio.write`, `device.flashlight.write`.
`device.settings.open` открывает страницу из фиксированного списка.
Яркость и тайм-аут требуют Android WRITE_SETTINGS. До Android 15 «Не беспокоить»
меняется после выдачи системного доступа. На Android 15+ современный APK не может
напрямую менять глобальный режим: действие возвращает `unsupported`, а отдельная
кнопка открывает настройки. Moru не создаёт скрытое правило приложения вместо
восстановления глобального режима. Недоступные датчики возвращают null с причиной.
Система сообщает память, хранилище и `system.uptimeMs` с момента загрузки.
`device.settings.open` принимает страницу из каталога; для `app_details` можно
передать `packageName` выбранного доступного приложения. URI или команды из
аргументов не исполняются. Открытие настроек требует видимого Moru.

Root-права раздельны: `device.root.power_save`, `device.root.wifi`,
`device.root.bluetooth`, `device.root.data`, `device.root.airplane`,
`device.root.stop_app`. Разрешены только фиксированные операции; выбранный
пакет проверяется заново, системные и защищённые приложения не останавливаются.
Операции ограничены по времени и выводу, результат перечитывается.
Ни окружение root, ни `root_shell` ассистента не выдают приложению эти права.
Формат 2 не принимает `server.command`: текущий PRoot не изолирует произвольный
shell от файлов и окружения Moru. Такой исполнитель требует отдельной модели
доступа в следующей части. Серверы старого формата 1 сохраняют прежнее поведение.

Wi-Fi-вход не получает новые права управления устройством. Для формата 2
изменение данных через Wi-Fi или фоновое задание также запрещено, включая
`moru.storage.set/remove` и фоновые действия состояния: событие изменения
не должно запускать локальное действие с более широкими правами. Чтение
данных остаётся доступно; фоновые чтения устройства проверяют выданные права
и возвращают снимок только заданию, без события открытой странице.
Задания и Wi-Fi-доступ к данным старого формата 1 сохраняют прежнее поведение.
Фоновые задания не выдают права и не выполняют новые изменения устройства.
В WebView формата 2
мост использует отдельный защищённый origin приложения и проверяет происхождение;
чужой iframe не получает доступ к привилегированным методам. Изменяющие действия
WebView требуют подтверждения: JavaScript не доказывает, что вызов сделан
нажатием пользователя. Кнопки нативной панели вызываются хостом напрямую.
Полный доступ снимает и эти подтверждения после проверки прав.

Результаты различают `applied`, `opened_settings`, `permission_required`,
`unsupported`, `denied`, `failed`, `unknown_after_timeout`. Открытые настройки
не означают изменения; тайм-аут не означает успеха. Пресеты сохраняют фактические
прежние значения, а восстановление проверяет, что пользователь не изменил их
позже. Частичный отказ и конфликт показываются отдельно.

Встроенный «Пульт телефона» — обычная нативная панель с теми же правами и
исполнителем, включая режимы «Ночь», «Дорога», «Работа» и восстановление.
Терминал/Termux, Shizuku, скриптовые VM, библиотеки, виджеты и новые фоновые
автоматизации в этой части не добавляются.
