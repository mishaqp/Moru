# Ядро мини-приложений 2.0

Версия Moru остаётся 0.1.47+48. Старый `moru-app.json` без `formatVersion`
считается форматом 1 и открывается в WebView. Его файлы, `moru.storage`,
задания, серверы, версии, экспорт и резервные копии сохраняются.

## Манифест и действия

```json
{
  "id": "brightness-panel",
  "name": "Яркость",
  "formatVersion": 2,
  "ui": {"engine": "native", "entry": "screen.json"},
  "permissions": ["actions.ai", "device.screen.read", "device.screen.write"],
  "actions": [{
    "name": "brightness",
    "description": "Изменить общую яркость",
    "inputSchema": {
      "type": "object",
      "properties": {"value": {"type": "integer", "minimum": 0, "maximum": 255}},
      "required": ["value"],
      "additionalProperties": false
    },
    "permissions": ["device.screen.write"],
    "danger": "write",
    "executor": {"kind": "native", "handler": "device.screen.brightness.set"}
  }]
}
```

`ui.engine` принимает `web` или `native`. Действие объявляет имя, описание,
исходную JSON Schema, права, опасность `read`/`write`/`root` и исполнителя.
Приложение не может ослабить права или подтверждение фиксированного обработчика.
Схема проверяется при установке и перед выполнением; неизвестные проверяемые
ограничения отклоняются. Корень аргументов описывает объект, включая локальные
ссылки и композиции объектных схем. Проверка ограничивает объём, глубину и
разворачивание ссылок; `pattern` принимает безопасное подмножество без групп,
альтернатив и обратных ссылок. Исходная схема сохраняется без переписывания.
Необязательный null, который исходная схема запрещает,
означает отсутствие аргумента; разрешённый null остаётся данными.

При включённом инструменте ассистента `mini_apps` действия становятся
`ma_`-инструментами с ограниченным именем и хешем app/action ID. Их имена
резервируются от коллизий с MCP. Для выполнения из ИИ приложение должно иметь
выданное пользователем право `actions.ai`; оно требуется и для записи/удаления
данных формата 2 через `mini_apps`. Обычный чат и ACP вызывают тот же
`MiniAppRuntime.execute`, что кнопка. Снимок маршрутов на время ответа не даёт
обновлению приложения подменить уже предложенное действие.

После публикации, отката и возврата версии можно продолжать в том же ответе
чата или ACP через стабильный инструмент `mini_apps`. Вызов `{"action":"list"}`
возвращает текущий токен `version` приложения и исходную `inputSchema` каждого действия.
Затем вызвать, например:

```json
{"action":"invoke","app_id":"focus","action_name":"start_25","version":"токен из list","arguments":"{}"}
```

Токен содержит время публикации и SHA-256 манифеста со схемами, правами и
исполнителями: совпавшее время не позволяет подменить контракт. Числовые ID
исторических версий для `rollback` по-прежнему берутся из `versions`;
возвращённая `version` предназначена для `invoke`.
`arguments` — строка с JSON-объектом, не более 64 КиБ UTF-8; это сохраняет
произвольную исходную схему без пустых object-схем в OpenAI/Gemini.
Версия обязательна: старый токен и старый `ma_`-инструмент отклоняются. Вызов
проверяет аргументы по актуальной исходной схеме и идёт через общий runtime,
с живыми правами, подтверждением и отменой. Замена приложения во время загрузки
или ожидания подтверждения также останавливает вызов. Для исправленного действия
нужно заново прочитать `list`; новое сообщение пользователя не требуется.

Базовые исполнители: `native` с фиксированным `handler`; `state` с
`patch`, где `{"$arg":"имя"}` подставляет аргумент; `preset` с ограниченным
списком `steps: [{handler, args}]`; `restore` без пользовательской записи
в журнал восстановления. Новые исполнители добавляются в проверку манифеста и
общий runtime. Интерфейсы экрана, чата и ACP сохраняются.

## Спецификация для ИИ и составные действия

Перед созданием панели вызвать `mini_apps {"action":"spec"}` или
`publish_mini_app {"action":"spec"}` без `path`. Ответ не читает приложения,
их данные или телефон: он содержит поля манифеста, все исполнители, выражения,
компоненты, имена привязок, точные схемы фиксированных обработчиков, права,
пределы и целые файлы `moru-app.json`/`screen.json` примеров «Фокус» и «Пульт телефона».
Достаточно записать эти JSON-объекты в папку и вызвать
`publish_mini_app {"path":"папка"}`. Старый вызов публикации без `action`
сохраняется; явный `"action":"publish"` тоже допустим. Ошибки в формате
указывают путь поля и допустимый вариант; результат публикации также напоминает,
как запросить спецификацию. Публикация не выдаёт прав приложению.

`sequence` объединяет объявленные действия одного приложения:

```json
{"kind":"sequence","steps":[
  {"action":"focus_preset","arguments":{},"onFailure":"continue"},
  {"action":"record_start","arguments":{"durationMs":1500000}}
]}
```

Шаги выполняются по порядку через тот же runtime, что отдельная кнопка или
инструмент. Права и опасность составного действия включают требования потомков;
согласие запрашивается для каждого изменяющего шага по обычным правилам.
`arguments` по умолчанию `{}`, `onFailure` — `stop`. Циклы запрещены;
глубина максимум 8, развёрнутых шагов максимум 32. Отзыв прав, отказ в согласии,
отмена и смена версии приложения прекращают цепочку, включая `continue`.
Явное `continue` допускает продолжение после обычного `failed`/`unsupported`
исполнителя, но сохраняет общий отказ и частичный результат. Ответ содержит
успешные `completedSteps`, первый `failedStep`, все `failedSteps` и `partial`.
Это не транзакция: уже выполненные действия остаются, автоматического отката нет.
Для восстановления добавьте отдельное объявленное действие `restore`.

## Безопасные выражения данных

Выражения включаются явно: `{"kind":"state","expressions":true,"patch":{…}}`.
Они вычисляются только в `state.patch`, без произвольного кода. Без флага (или
с `false`) действует прежняя запись JSON и `$arg`: даже литералы с ключами
`$now`/`$inc` сохраняют прежний смысл. Весь patch
записывается атомарно; выражения читают данные до этой записи и одно общее время.
Обычные JSON-значения и неизвестные ключи с `$` сохраняются как раньше;
только распознаваемые операторы вычисляются и проверяют типы.

| Выражение | Результат |
| --- | --- |
| `{"$arg":"minutes"}` | Значение аргумента действия |
| `{"$data":"sessionsToday"}` | Значение по пути относительно данных; отсутствующее — null |
| `{"$inc":1}` / `{"$dec":1}` | Прибавить / убавить от прежнего числа в записываемом поле; отсутствующее начинается с 0 |
| `{"$now":true}` | Текущее время в миллисекундах Unix |
| `{"$today":true}` | Локальная дата `YYYY-MM-DD` |
| `{"$add":[{"$now":true},1500000]}` | Числовая сумма: срок через 25 минут |
| `{"$eq":[a,b]}` | Равенство двух JSON-значений |
| `{"$if":[условие,да,нет]}` | Выбрать ветку; невыбранная не вычисляется |

Пример остановки с дневным счётчиком (повторный стоп не прибавляет сессию):

```json
{"kind":"state","expressions":true,"patch":{
  "sessionsToday":{"$if":[{"$eq":[{"$data":"running"},true]},
    {"$if":[{"$eq":[{"$data":"sessionDay"},{"$today":true}]},{"$inc":1},1]},
    {"$data":"sessionsToday"}]},
  "sessionDay":{"$today":true},"running":false
}}
```

Выражения ограничены по глубине, объёму и числу вычислений; обычные данные
сохраняют прежние пределы шаблонов.
Ошибки типов и превышение ограничений выражений не оставляют
полузаписанного patch. `$arg` в аргументах preset/sequence остаётся шаблонной
подстановкой; выражения данных там не исполняются. `$value` используется только
в аргументах элементов управления для выбранного значения.

## Экран и состояние

```json
{
  "version": 1,
  "components": [{
    "type": "card", "title": {"ru": "Экран", "en": "Screen"},
    "children": [{
      "type": "slider", "label": {"ru": "Яркость", "en": "Brightness"},
      "bind": "device.screen.brightness", "min": 0, "max": 255, "step": 1,
      "action": "brightness", "args": {"value": {"$value": true}}
    }]
  }]
}
```

Компоненты: `card`, `text`, `value`, `button`, `switch`, `slider`, `list`,
`indicator`, `timer`, `progress`. Числовой индикатор показывает шкалу между `min` и `max`, логический —
состояние. `bind` читает путь в `data`, `device` или `revision`.
`action` ссылается на объявленное действие; `$value` подставляет значение
контрола. Ползунок применяет значение при отпускании. Строки могут содержать
карты локалей. JSON ограничен по размеру, глубине и числу компонентов;
исполняемых строк и загружаемых плагинов нет.

`mini_apps` с `action: state` читает снимок открытого или закрытого приложения.
WebView формата 2 использует `moru.actions.invoke(name, args)`,
`moru.state.get()`, `moru.state.subscribe(listener)` и `moru.device.*`.
Подписка возвращает функцию отмены. Снимок содержит `data`, отфильтрованный
по выданным правам `device` и `revision`. Android сообщает реальные изменения;
при возвращении из настроек экран перечитывает их. Закрытая нативная панель
не держит WebView, сервер, процессы или постоянный наблюдатель Android.

### Время на нативной панели

```json
{"version":1,"components":[
  {"type":"timer","label":"Осталось","bind":"data.endsAt","mode":"countdown"},
  {"type":"progress","label":"Сессия","bind":"data.endsAt","startBind":"data.startedAt"},
  {"type":"value","label":"Начало","bind":"data.startedAt","format":"datetime"}
]}
```

`timer` принимает время Unix в миллисекундах: `countdown` (по умолчанию)
считает до `bind`, `elapsed` — от `bind`; результат `H:mm:ss` не уходит ниже нуля.
`progress` показывает долю `(сейчас − startBind)/(bind − startBind)` от 0 до 1.
Недостающие или неверные времена показаны как недоступные. `value`/`indicator`
поддерживают `date`, `time`, `datetime` для времени Unix или ISO-строки,
с форматированием по языку приложения; прежние `bytes`/`duration` сохраняются.
Один секундный тик существует только для активного видимого экрана, выключается
при уходе с панели/сворачивании и удаляется при закрытии. Истёкший отсчёт не
создаёт фоновое задание и сам не вызывает действие: остановка и восстановление
выполняются кнопкой или ИИ.


## Доступ к телефону

Пользователь выдаёт и отзывает отдельные права на экране приложения.
Установка и обновление не выдают новых прав; grants и журнал восстановления
хранятся отдельно от доступного приложению `data.json` и экспорта `.moruapp`.
Полный доступ снимает подтверждение Moru, сохраняя права приложения,
Android-разрешения, типы, пределы и список операций. После ожидания согласия
проверяются актуальные права, версия и владелец вызова.

Группы чтения: батарея, экран, звук, связь, фонарик и система. Для записи:
`device.screen.write`, `device.audio.write`, `device.flashlight.write`.
`device.settings.open` открывает страницу из фиксированного списка.
Яркость и тайм-аут требуют Android WRITE_SETTINGS. До Android 15 «Не беспокоить»
меняется после выдачи системного доступа. На Android 15+ современный APK не может
напрямую менять глобальный режим: действие возвращает `unsupported`, а отдельная
кнопка открывает настройки. Moru не создаёт скрытое правило приложения вместо
восстановления глобального режима. Недоступные датчики возвращают null с причиной.
Система сообщает память, хранилище и `system.uptimeMs` с момента загрузки.
`device.settings.open` принимает страницу из каталога; для `app_details` можно
передать `packageName` выбранного доступного приложения. URI или команды из
аргументов не исполняются. Открытие настроек требует видимого Moru.

Root-права раздельны: `device.root.power_save`, `device.root.wifi`,
`device.root.bluetooth`, `device.root.data`, `device.root.airplane`,
`device.root.dnd`, `device.root.stop_app`. Разрешены только фиксированные операции; выбранный
пакет проверяется заново, системные и защищённые приложения не останавливаются.
Операции ограничены по времени и выводу, результат перечитывается.
Ни окружение root, ни `root_shell` ассистента не выдают приложению эти права.

`device.root.dnd.set` принимает только `mode`, например `{"mode":"priority"}`.
Хост строит фиксированную команду `/system/bin/cmd notification set_dnd MODE`:
`all` выключает DND, `priority` оставляет важные уведомления, `alarms` — будильники,
`none` блокирует прерывания. Произвольные shell-строки и argv не принимаются.
Используются общий root-таймаут, отмена и проверка результата чтением глобального
фильтра Android; успешный выход команды сам по себе не означает `applied`.
Отказ, отсутствие доступа и неподдерживаемая команда не присваивают приложению
ручную смену DND во время ожидания root. После таймаута запись восстановления
возможна только при прочитанном запрошенном режиме; несовпавший режим не считается
изменением этого пресета.

Если приложение объявило и пользователь выдал `device.root.dnd`, обычные
действия и шаги пресета `device.audio.dnd.set` выбирают root-операцию перед
подтверждением. Права исходного действия остаются обязательными; подтверждение
показывает root-опасность и конкретную операцию. Во время вызова выбор не меняется:
отзыв права останавливает его. Журнал пресета хранит фактически использованный
обработчик, прежний и прочитанный новый режим. Восстановление требует его живого
права и отдельного root-подтверждения, сохраняет ручные изменения как конфликт.
Без root-права остаются обычный Android-путь и переход в настройки на Android 15+.
Формат 2 не принимает `server.command`: текущий PRoot не изолирует произвольный
shell от файлов и окружения Moru. Такой исполнитель требует отдельной модели
доступа в следующей части. Серверы старого формата 1 сохраняют прежнее поведение.

Wi-Fi-вход не получает новые права управления устройством. Для формата 2
изменение данных через Wi-Fi или фоновое задание также запрещено, включая
`moru.storage.set/remove` и фоновые действия состояния: событие изменения
не должно запускать локальное действие с более широкими правами. Чтение
данных остаётся доступно; фоновые чтения устройства проверяют выданные права
и возвращают снимок только заданию, без события открытой странице.
Задания и Wi-Fi-доступ к данным старого формата 1 сохраняют прежнее поведение.
Фоновые задания не выдают права и не выполняют новые изменения устройства.
В WebView формата 2
мост использует отдельный защищённый origin приложения и проверяет происхождение;
чужой iframe не получает доступ к привилегированным методам. Изменяющие действия
WebView требуют подтверждения: JavaScript не доказывает, что вызов сделан
нажатием пользователя. Кнопки нативной панели вызываются хостом напрямую.
Полный доступ снимает и эти подтверждения после проверки прав.

Результаты различают `applied`, `opened_settings`, `permission_required`,
`unsupported`, `denied`, `failed`, `unknown_after_timeout`. Открытые настройки
не означают изменения; тайм-аут не означает успеха. Пресеты сохраняют фактические
прежние значения, а восстановление проверяет, что пользователь не изменил их
позже. Частичный отказ и конфликт показываются отдельно.

Встроенный «Пульт телефона» — обычная нативная панель с теми же правами и
исполнителем, включая режимы «Ночь», «Дорога», «Работа» и восстановление.
В новых копиях режим и восстановление — составные действия; название и время
последнего успешного применения записываются в данные, время форматируется
на панели. Частичный отказ не записывается как успешный режим.
Терминал/Termux, Shizuku, скриптовые VM, библиотеки, виджеты и новые фоновые
автоматизации в этой части не добавляются.

## Встроенный «Фокус»

Новая панель предлагает 15/25/50 минут. Старт сохраняет прежние параметры,
пробует включить «Не беспокоить», ставит яркость 77 из 255 (30 %) и медиа 0,
затем записывает начало/срок и признак сессии. Новые копии «Пульта телефона» и
«Фокуса» объявляют отдельное право root DND; после его выдачи действия, пресеты
и восстановление используют фиксированную root-операцию, включая Android 15+.
При `unsupported` DND
(в частности Android 15+) показывается частичный результат и причина, но таймер
запускается; отдельная кнопка открывает системные настройки. Недостающие права
приложения или системные разрешения и отказ в подтверждении останавливают
цепочку; уже изменённые настройки можно восстановить кнопкой стоп.
Стоп один раз засчитывает запущенную сессию за сегодняшний день и вызывает
восстановление только сохранившихся прежних значений. После закрытия нет
процесса таймера; при открытии остаток вычисляется из сохранённого срока.
«Пульт телефона» и «Фокус» устанавливаются как обычные приложения через
проверку манифеста. Уже существующие экземпляры, данные и права не перезаписываются.
