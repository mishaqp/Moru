# Контракт схем инструментов

Исходная схема принадлежит инструменту, а не провайдеру. Она остаётся в каталоге,
MCP-кэше и настройках без изменений. Версия приложения — 0.1.47+48.

Действия мини-приложений формата 2 сохраняют `inputSchema` без изменений и
попадают в этот же путь как динамические `ma_`-инструменты. ACP передаёт
исходную схему через `AcpMcpServer`; допустимые имена берутся из проверенного
реестра приложения, включая сопоставление с карточкой агента. Снимок маршрутов
на время ответа связывает схему с версией приложения. Исполнитель проверяет
исходные аргументы и фиксированный контракт Android отдельно от нормализатора.

## Цепочка

1. `BuiltInToolCatalog`, `LocalToolsService`, workspace/memory/search и MCP
   предоставляют исходные function definitions. MCP больше не проходит отдельный
   `_sanitizeNode`, который выбирал первый тип или вариант объединения.
2. `ToolSchemaOverrides.apply` меняет только описания встроенных инструментов
   и существующих параметров. MCP получает свои сохранённые описания. Формат
   пользовательских переопределений и настроек не меняется.
3. Адаптер собирает native request и применяет `customBody`/`extraBody` и hosted
   tools. **После этих действий**, перед кодированием каждого запроса,
   `tool_schema_normalizer.dart` выполняет единственную конвертацию для провайдера.
   Повторные запросы после tool result проходят ту же границу.
4. Общая часть копирует схему, ограниченно раскрывает локальные `$ref`/`$defs`,
   сохраняет все ветки объединений, переводит `const` в `enum`, type-массивы и
   `nullable` в объединения с `null`. Boolean-схемы становятся `{}`/`not: {}`;
   старые tuple `items` — `prefixItems`. Циклы сохраняют ссылки и определения;
   внешние/неразрешимые ссылки получают пояснение, без сетевого разрешения.

Прежние `sanitizeToolParametersForProvider` и `cleanSchemaForGemini` оставлены
как совместимые оболочки над тем же нормализатором. Production не выполняет
через них дополнительную раннюю конвертацию.

| Путь | Правила |
| --- | --- |
| OpenAI Chat Completions, обычный | Общая JSON Schema; ограничения, объединения и `additionalProperties` сохраняются. Явный `strict: true` включает проверку следующего пути. |
| OpenAI strict, включая Responses по умолчанию | Только совместимые схемы: корень object, все объекты закрыты `additionalProperties: false`, все свойства required, прежние необязательные свойства допускают null. Сохраняются поддерживаемые enum/pattern/minimum/maximum/multipleOf и границы строк/массивов. |
| Claude, включая Vertex Claude | Общая JSON Schema в `input_schema`, без strict-переписывания. |
| Gemini, включая Vertex Gemini | Подмножество REST OpenAPI Schema: допустимые поля, строковые enum, minimum/maximum, pattern, границы строк/массивов/объектов. nullable сохраняется; anyOf включает все совместимые типы. allOf пересекает ограничения, свойства и required; oneOf получает anyOf и пояснение об исключительности. |

Strict несовместим со свободными словарями, произвольным JSON, неподдерживаемыми
комбинаторами/ключевыми словами/форматами и превышением лимитов схемы. Проверяются
10 уровней контейнеров, 5000 свойств, 1000 enum-значений, 120000 символов имён и
enum; для строкового enum с более чем 250 значениями — 7500 символов. В таком
случае **весь инструмент получает `strict: false` и обычную схему**. `default`
не передаётся в strict. Явный `strict: false` сохраняется и в Responses.

У Gemini нет точного представления всех JSON Schema ограничений. Непредставимые
ограничения (например, additionalProperties, not, tuple, числовой/boolean enum)
переносятся в описание, с diagnostics по пути/ключевому слову. Это подсказка
модели; исходная проверка остаётся у обработчика/сервера. Произвольный JSON
получает явное объединение JSON-типов; для неограниченного вложенного массива
используется описанное приближение. Нельзя считать OpenAPI-схему полной проверкой
исходного JSON Schema. Исходные значения enum не превращаются в другие строки.

## Отсутствие и null

Strict-null у необязательного поля означает отсутствие изменения. Device bridge,
spend, assistant manager и расписания пропускают такие поля; явные пустые строки,
массивы и `clear` сохраняют прежний смысл. `mini_apps.value: null` — данные,
а `manage_mcp.config.cwd/workspaceId: null` — документированный сброс; поэтому
эти инструменты не принуждаются к strict.

Перед реальным `McpProvider.callTool` `omitUnsupportedOptionalNulls` сверяется
с **исходной** схемой (legacy params используют тот же
`McpToolService.sourceParameters`, что и объявление): удаляет только null у необязательного поля, которое null
не допускает. Обходит ссылки, объединения, вложенные объекты и элементы массивов.
Required-null, допустимый null и неизвестные аргументы остаются для проверки
MCP-сервером. Переданная приложению карта аргументов не изменяется.

## Изменившиеся схемы

- OpenAI strict/Responses: весь совместимый каталог получает закрытые объекты,
  required и nullable для optional. `browser_use`, `manage_assistants`, `mini_apps`
  получают fallback; `manage_mcp` явно остаётся non-strict. Chat Completions без
  strict и Claude меняют встроенный `manage_mcp`: его nullable/type-массивы
  канонизируются в anyOf. Семантика сброса сохранена.
- Gemini: `browser_use`, `manage_assistants`, `manage_mcp`, `mini_apps`,
  `phone_control`, `report_problem`, `spend_control` получают канонические типы
  или описания ограничений, которых нет в REST Schema. Для остальных встроенных
  инструментов форма параметров совпадает с исходной.
- MCP для всех провайдеров: больше не теряет минимум/максимум, nullable и остальные
  варианты типа; вложенные ссылки раскрываются без выбора первой ветки. У Gemini
  неподдерживаемые ограничения становятся пояснениями; у strict — fallback.
- Описания `manage_assistants`, `report_problem` и calendar_create уточнены отдельно:
  редактировать нужно исходные настройки, полный доступ исключает подтверждение,
  all-day end по умолчанию — следующий местный день.

## Проверки

`tool_schema_normalizer_test.dart` получает **весь** каталог автоматически: все
языки memory, оба режима памяти и все локальные определения, включая отключённые
Android-инструменты. MCP-фикстуры содержат nullable, anyOf/oneOf/allOf, refs/defs,
nested/array objects, enum, minimum/maximum, словари, пустые и boolean-схемы, tuple.
Для каждого источника проверяются четыре пути, правила формы и отсутствие мутации.
`tool_schema_edge_cases_test.dart` проверяет смысл пересечений и границы strict.
`tool_schema_provider_request_test.dart` проверяет HTTP-body всего каталога для
CC обычного/strict, Responses обычного/strict, Claude/Gemini и body overrides;
отдельно проверяет два tool-round Vertex Claude. Names-тест сравнивает
`LocalToolNames.all`, `BuiltInToolNames.all` и каталог, включая MCP-коллизии.

Проверки транспорта используют локальные HTTP-ответы. Запросы к живым API
провайдеров и исполнение Android-инструментов на телефоне остаются отдельной
проверкой; они не подменяются проверкой формы JSON.
