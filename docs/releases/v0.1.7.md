## Паритет с rikkahub-agent

Продолжение работы над `browser_use` в сторону возможностей форка rikkahub-agent:

- Исправлен ввод в `<select>`: раньше значение выставлялось напрямую и React (и другие фреймворки с собственным трекером состояния) мог не замечать изменение — теперь используется тот же приём, что уже применялся для `<input>`/`<textarea>`.
- Новое действие `wait_for`: ждёт, пока CSS-селектор достигнет состояния (`attached`/`detached`/`visible`/`hidden`), с опциональной проверкой текста — не требует подтверждения.
- Новое действие `eval_js`: выполнение произвольного JS на странице для задач, не покрытых остальными действиями. Код проверяется по списку запрещённых паттернов (`document.cookie`, `eval`/`Function`, строковые `setTimeout`/`setInterval`) до передачи в WebView; подтверждение требуется как для остальных мутирующих действий и подчиняется общему переключателю полного доверия — без исключений.
- Новые действия `submit` (отправка формы) и `press_key` (синтез события клавиатуры, например Enter).

## Настройки → Браузер

Раньше `browser_use` не был виден в настройках инструментов вовсе — либо доступен целиком, либо выключен только общим переключателем полного доверия. Добавлена отдельная страница **Настройки → Браузер** с переключателем на каждое из 14 действий по отдельности, сгруппированных как «Чтение» (никогда не требуют подтверждения) и «Запись» (требуют подтверждения, если не включено полное доверие).

## Плавающая строка «Спросить ИИ» в браузере

В окне браузера появилось поле ввода снизу: можно дать ИИ новую команду прямо во время просмотра страницы, не возвращаясь в чат. Во время выполнения показывается индикатор «ИИ работает…» с кнопкой «Стоп».

## Известные ограничения

- Новые действия браузера (`wait_for`, `eval_js`, `submit`, `press_key`) и плавающая строка проверены модульными и виджет-тестами, но не подтверждены сквозным тестированием на реальном устройстве в рамках этого релиза.
- Рендеринг самой строки «Спросить ИИ» внутри `WebViewPage` не покрыт автоматическими тестами — в проекте пока нет инфраструктуры для мока платформенного WebView; покрыта вся логика, от которой она зависит (мост запросов/ответов и разрешение диалога/ассистента).

## Проверки и APK

Перед публикацией workflow выполняет полный Dart analyze, Flutter tests, Android JVM tests, проверку arm64 ABI, release-подписи и package metadata.

Один **arm64-v8a release APK**, версия **0.1.7**, versionCode **8**, пакет `com.mishaqp.moru`. Используется постоянный сертификат Moru; релиз предназначен для установки поверх предыдущего подписанного Moru без удаления данных.
