# Moru v0.1.40 — второй проход по разделу «Провайдеры»

Что делать, выбрали перед началом работы: удалить мёртвый код и разбить большие файлы раздела. Поведение экранов не менялось, кроме одного исправления.

## Проход по разделу «Провайдеры»

### Исправление

- **Несколько ключей.** Если в окне «Добавить» один и тот же ключ встречался дважды (например, `k1, k2 k1`), он добавлялся двумя одинаковыми записями. Теперь каждый новый ключ добавляется один раз. Ключи, которые уже есть в списке, по-прежнему пропускаются.

### Удалённый код

- Закомментированный список провайдеров, которых нет в приложении (Hunyuan, Kimi, StepFun, MiniMax, Mistral и другие).
- Закомментированные строки вибрации и значка баланса.
- Параметр `haptics` у кнопки на экране провайдера, который ничего не делал.
- Вход через OAuth:
  - условие «не Android и не iOS» у кнопки «Открыть в браузере»;
  - iOS-вариант возврата из браузера после входа;
  - заглушка для Web.
- Вход в Claude по подписке: определение ОС для заголовка запроса. На Android там всегда было `Linux`, теперь это записано прямо.
- Файлы Claude: десктопный лимит 500 МБ. На телефоне лимит был и остаётся 200 МБ.

Итого по удалению: 9 файлов, −114 / +6 строк.

### Разбиение файлов

Код перенесён без изменений, поменялось только расположение.

### Что не менялось

- Экраны раздела по-прежнему следят за всеми настройками. Замер (отладочный тест, 20 провайдеров): открытый список провайдеров тратит около 50 мс на каждое постороннее изменение настроек, а спрятанный под экраном провайдера — около 37 мс на каждый введённый символ ключа или адреса. Этот пункт отложили, бенчмарк `test/perf/providers_section_bench.dart` остался для следующего прохода.
- Поиск в выборе модели: около 83 мс на символ при 1000 моделях. Тоже отложено.
