## Исправлен браузерный Ask-AI: ответ теперь виден в самом браузере

В v0.1.11 переработка браузера содержала регрессию: ответ ассистента на вопрос из плавающей строки «Спросить ИИ» появлялся в обычном чате, но никогда не показывался в самой карточке ответа внутри браузера — пользователь видел действия агента, а затем композитор просто возвращался в исходное состояние без ответа.

- **Причина**: `ChatActions.sendMessage` подтверждает лишь факт *запуска* генерации — реальная работа идёт в фоне (`unawaited`), а метод сразу возвращает пустое сообщение-заготовку, чтобы не блокировать поле ввода. Раннер браузерного Ask-AI ошибочно принимал эту заготовку за готовый ответ и немедленно сообщал его браузеру — с пустым текстом, поэтому карточка ответа тихо не показывалась.
- **Исправление**: добавлено единое событие завершения генерации (`GenerationTerminalEvent`), которое эмитится из той самой точки кода, через которую уже проходят все варианты завершения — обычный успех, ошибка, ручная остановка и ошибка подготовки до начала стриминга — и только после того, как результат действительно записан. Раннер браузерного Ask-AI подписывается на этот поток ещё до вызова `send()` (чтобы не потерять мгновенное завершение) и дожидается события именно своего запроса, беря окончательный текст из настоящего сообщения чата, а не из заготовки. Контракт `send()` не изменился — поле ввода освобождается сразу же, как и раньше.
- Заодно корректно учтены остановка запроса до завершения генерации, ошибка после успешного старта, гонка с мгновенным ответом, поздний ответ после закрытия браузера и повторные события — без второго запроса к модели, дублей сообщений или опроса по таймеру.

## Известные ограничения

- Исправление покрыто модульными и виджет-тестами (включая тест полной цепочки: раннер → мост Ask-AI → контроллер панели → карточка ответа). Реальная проверка на физическом Android-устройстве этим релизом не проводилась — рекомендуется ручной smoke-тест после установки: задать вопрос ИИ из браузера и убедиться, что ответ появляется в самой карточке над страницей.

## Проверки и APK

Перед публикацией workflow выполняет полный Dart analyze, Flutter tests, Android JVM tests, проверку arm64 ABI, release-подписи и package metadata.

Один **arm64-v8a release APK**, версия **0.1.12**, versionCode **13**, пакет `com.mishaqp.moru`. Используется постоянный сертификат Moru; релиз предназначен для установки поверх предыдущего подписанного Moru без удаления данных.
