## Паритет с rikkahub-agent

Ещё два пункта из сравнения `browser_use` с возможностями форка rikkahub-agent:

- Новое действие `done`: явный сигнал модели, что задача в браузере выполнена, с опциональным `summary` — показывается в статус-строке браузера. Не требует подтверждения, не меняет страницу.
- Журнал активности браузера (`BrowserAgentSession.currentActivity`/`recentActivity`) теперь хранит исход каждого шага — `running`/`ok`/`failed` — а не только сам факт вызова. Статус-бар и лист «Recent» показывают явную отметку «— не удалось» только при реальной неудаче.

## Настройки → Браузер

Список переключаемых действий вырос с 14 до 15 (добавился `done`).

## Известные ограничения

- `done` и отслеживание исхода покрыты модульными тестами (`browser_agent_session_activity_test.dart`, `local_tools_service_test.dart`), но не подтверждены сквозным тестированием на реальном устройстве в рамках этого релиза.

## Проверки и APK

Перед публикацией workflow выполняет полный Dart analyze, Flutter tests, Android JVM tests, проверку arm64 ABI, release-подписи и package metadata.

Один **arm64-v8a release APK**, версия **0.1.8**, versionCode **9**, пакет `com.mishaqp.moru`. Используется постоянный сертификат Moru; релиз предназначен для установки поверх предыдущего подписанного Moru без удаления данных.
