## Исправление входа Codex на Android

По журналу с телефона браузер и аккаунт успешно проходили авторизацию Codex, но Moru периодически терял DNS-разрешение `auth.openai.com` между успешными OAuth-запросами. Это обрывало как `device-poll`, так и обмен кода на токены.

- OAuth теперь повторяет только подтверждённые ошибки DNS с короткой задержкой и новым HTTP-запросом.
- HTTP-ответы, TLS-ошибки, таймауты и прочие транспортные ошибки не повторяются, чтобы не рисковать повторной отправкой одноразового authorization code после неизвестного результата на сервере.
- Тело запроса, PKCE и параметры входа сохраняются без изменений между DNS-повторами.
- Диагностика остаётся безопасной: коды входа, токены, PKCE и URL-параметры в журнал не попадают.
- Вход остаётся через аккаунт ChatGPT; тариф Pro берётся из данных аккаунта, API-ключ не подставляется и тариф не назначается искусственно.

## Проверка

Регрессионный тест сначала воспроизвёл текущий сбой (`OAuth: network` после `Failed host lookup`), затем прошёл после исправления: два последовательных DNS-сбоя и успешная третья попытка с неизменным OAuth form body. Полный анализ, Flutter-тесты, Android JVM-тесты, проверка ABI и подписи выполняются релизным workflow перед публикацией.
