# Moru v0.1.36 — исправления мини-приложений

## Исправления

- **Напоминания мини-приложений не ставились.** В сборке для телефона `moru.reminders.set` падал с ошибкой `PlatformException: Missing type parameter`.
  - Причина: библиотека уведомлений хранит запланированные уведомления в JSON и читает их через Gson. Оптимизатор R8 в release-сборке вырезал информацию о типах, которая Gson для этого нужна. Та же ошибка сработала бы при восстановлении уведомлений после перезагрузки телефона.
  - В правила R8 добавлены исключения для Gson и библиотеки уведомлений. Проверено на собранном APK: у класса, через который читаются уведомления, сигнатура типа теперь на месте, в 0.1.35 её не было.
- **`moru.ai.ask` требовал модель по умолчанию.** Если модель выбрана только у ассистента, приложение получало ошибку «Choose a default model». Теперь используется тот же порядок, что и в чате: модель текущего ассистента, а если её нет — модель по умолчанию.

## Дальше

- 0.1.37: автопроверка мини-приложения в невидимом браузере, календарь, доступ в интернет по списку адресов, обмен файлом `.moruapp`, проход по разделу «Внешний вид и поведение».

## Проверка

- Новые тесты выбора модели для `moru.ai.ask`: модель ассистента без модели по умолчанию, модель ассистента важнее модели по умолчанию, запасной вариант, ошибка без модели.
- Release-APK проверен разбором dex: у наследника `TypeToken` в библиотеке уведомлений есть generic-сигнатура.
- Анализ без замечаний, полный набор Flutter-тестов.
- CI: анализ, Flutter-тесты, локализация, Android JVM-тесты и сборка одного `arm64-v8a` APK, подписанного постоянным сертификатом Moru.
