# Moru v0.1.37 — мини-приложения: интернет, календарь, обмен и автопроверка

## Изменения

- **Автопроверка после публикации.** Когда агент публикует приложение через `publish_mini_app`, Moru сам открывает его в невидимом окне и через пару секунд возвращает агенту отчёт `check`:
  - ошибки скриптов и необработанные ошибки в промисах;
  - файлы, которые не загрузились;
  - вызовы `moru.*`, которые вернули ошибку;
  - ошибки и предупреждения консоли;
  - «пустой экран», если на странице нет ни текста, ни картинок.

  Агент исправляет найденное и публикует заново, прежде чем дать ссылку.
  - Проверка работает на копии приложения: настоящие данные и напоминания не меняются, уведомления не приходят, модель не вызывается, в календарь ничего не пишется.
  - Если проверку не удалось запустить, публикация всё равно проходит, и агент попросит открыть приложение вручную.
- **Интернет по списку адресов.** В `moru-app.json` приложение перечисляет домены в поле `network`, например `["api.open-meteo.com", "*.example.org"]`.
  - Запросы делаются через `moru.fetch(url, {method, headers, body})`. Ответ содержит `status`, `ok`, `headers`, `body` и `json()`.
  - `moru.fetch` не ограничен CORS, поэтому работают API, которые обычный `fetch()` из страницы не пускает.
  - Домены вне списка отклоняются. Перенаправления Moru обрабатывает сам и тоже проверяет по списку.
  - Лимиты: запрос до 1 МБ, ответ до 2 МБ, до 20 доменов.
- **Календарь.** Приложение с `"permissions": ["calendar"]` в манифесте может:
  - читать события через `moru.calendar.list({range: "today" | "week" | "month", begin, end, query})`;
  - добавлять события через `moru.calendar.add({title, start, end, description, location, all_day, reminders})`.

  Разрешение на календарь Moru спросит при первом обращении.
- **Обмен приложениями файлом `.moruapp`.**
  - В меню приложения в «Мои приложения» появился пункт «Поделиться». Если у приложения есть данные, Moru спросит: «Только приложение» или «Приложение и данные». Напоминания не передаются.
  - Файл устанавливается кнопкой «Импорт» в «Мои приложения» или открытием `.moruapp` через «Поделиться» / «Открыть с помощью» в Moru.
  - Данные из файла используются, только если у этого приложения на телефоне ещё нет своих, поэтому импорт никогда не затирает ваши записи.
  - Повреждённые файлы и файлы с опасными путями отклоняются.
- **Проверка release-сборки в CI.** Ошибку напоминаний из 0.1.35 можно было увидеть только в release-APK, потому что для PR собирается debug, где R8 не работает. Теперь сборка на `master` проверяет готовый APK: если R8 снова вырежет информацию о типах, нужную библиотеке уведомлений, APK не пройдёт проверку и не будет опубликован. Проверка испытана на настоящих APK: 0.1.35 она не пропускает, 0.1.36 пропускает.

## Дальше

- 0.1.38 и далее: оптимизация, улучшения и удаление ненужного кода по разделам. Начнём с «Внешний вид и поведение» и доделаем остальные экраны «Провайдеров».

## Проверка

- Новые тесты:
  - `moru.fetch`: разрешённые и запрещённые домены, `*.домен`, схемы и методы, перенаправление на чужой домен не выполняется, перенаправление внутри списка выполняется (POST → GET после 303), лимит ответа;
  - манифест: `network` и `permissions` сохраняются, неверные значения отклоняются;
  - календарь: без разрешения в манифесте не вызывается, передаются только свои поля, ошибки устройства доходят до страницы;
  - `.moruapp`: экспорт и установка в другом месте с файлами и данными, без данных, импорт не затирает существующие данные, повреждённые и опасные файлы отклоняются без следов;
  - автопроверка: копия видит данные, но не меняет настоящие, заглушки для модели, уведомлений и календаря, сбор ошибок, `check` в ответе `publish_mini_app`, публикация проходит при сбое проверки;
  - проверка release-APK на синтетическом dex.
- Анализ без замечаний, полный набор Flutter-тестов.
- CI: анализ, Flutter-тесты, локализация, Android JVM-тесты и сборка одного `arm64-v8a` APK, подписанного постоянным сертификатом Moru.

Версия **0.1.37** (`versionCode 38`), пакет `com.mishaqp.moru`.
