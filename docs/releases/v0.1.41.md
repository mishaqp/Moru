# Moru v0.1.41 — проход по разделу «Хранилище»

Что делать, выбрали перед началом работы: удалить десктопный код и разбить файл экрана. Поведение экранов на Android не менялось.

## Проход по разделу «Хранилище»

### Удалённый код

- Десктопная раскладка экрана: боковое меню категорий и панель с подробностями справа.
- Десять методов очистки на главной странице: кэш, прочий кэш, системный кэш, логи, старые данные чатов, следы восстановления, вытесненные базы, шрифты, локальные модели и файлы потерянных сессий. Их вызывала только десктопная раскладка. На Android очистка всегда шла со страницы категории, там всё осталось.
- Параметр `embedded` для встраивания экрана в десктопные настройки.
- Экспорт старых файлов чатов через десктопное окно «Сохранить как». На Android экспорт всегда шёл через системное сохранение, так и осталось.
- Десктопный переход к просмотру картинок.
- Исключение локальных копий из резервного копирования iCloud и проверки «Web / не Android и не iOS» при определении свободного места.

Итого: −698 строк в `lib`.

### Разбиение файла

`storage_space_page.dart` был 2941 строку. Без десктопного кода он разбит на части, код перенесён без изменений.

| Часть | Строк |
|---|---|
| Главная страница: общий размер, полоса, список категорий | 377 |
| Страница категории: подробности и очистка | 932 |
| Файлы и изображения: список, фильтры, сортировка, выбор, удаление | 739 |
| Мелкие виджеты | 222 |

### Что не менялось

- Подсчёт размера. Замер на 5000 файлах в данных приложения: около 1,07 с на подсчёт, а тот же обход в фоновом потоке занимает 52 мс. Ускорение отложили, бенчмарк `test/perf/storage_usage_bench.dart` остался для следующего прохода.
